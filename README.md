# Gesture Control for macOS V1.5 — 双手协同控制

## V1.5：左手锁定 + 右手连续操作 / 复制 / 粘贴

- 启用「双手联动」后，物理右手负责操作，物理左手拇指与食指先张开再捏合保持 300ms，锁定当前滚动、拖拽或已启用的缩放。
- 连续滚动保持锁定瞬间的方向及速度；右手可恢复指针移动、点击或执行独立的复制粘贴快捷手势。
- **右手先保持单指指针姿态 200ms 准备**。握拳稳定 500ms 执行 **⌘C 复制**；张开手掌稳定 500ms 执行 **⌘V 粘贴**。每次执行后需重新回到单指姿态准备，不能凭持续握拳或直接切换到张掌连续触发。
- 复制与粘贴仅在左手锁定**滚动或缩放**时生效；拖拽按键被锁定、右手仍在拖拽、双手模式关闭或右手身份不可靠时不会发快捷键。
- 左手张开并持续 80ms 解除锁定；左手检测丢失 250ms、连续摄像头帧停滞超过看门狗期限、模式切换或停止应用时自动停止输出，拖拽最终释放鼠标左键。
- 首次使用请允许「辅助功能」与「相机」权限。复制/粘贴属于模拟全局快捷键，作用于当前焦点应用及其当前选区。
- 顶部非激活、可穿透鼠标的透明 HUD 显示锁定与快捷键状态；可独立关闭。双手检测默认关闭以节省资源。

> 真实摄像头光照、左右手 chirality、屏幕镜像、应用选区与不同软件对 ⌘C/⌘V 的处理，需要在实际 Mac 上按下文场景验收；CI 自动测试不等价于实机确认。

纯本地 macOS 空中触控板 / 手势控制工具。使用 Swift + AVFoundation + Apple Vision + Core Graphics，本机处理摄像头画面，不依赖 Python、MediaPipe、Electron 或云端 AI。

## V1.2.2 持续优化

- Bundle 版本统一由 Xcode build settings 生成，构建脚本从最终 App 读取版本，消除版本漂移；
- CI 同时编译 Debug / Release，并将 Xcode 并发限制为 2，提升 SwiftCompile 失败的可诊断性；
- Vision 手掌中心改为单次累加，不再为每只手每帧创建临时数组，finger pattern 也避免重复 joint 查找；
- 指针/滚动历史窗口改为有序前缀裁剪，滚动释放估计不再创建临时 filter 数组；
- 停止、摄像头错误和旧回调之后统一禁止新的合成输入，并确保左键释放，避免“幽灵拖拽”；
- 持久化数值设置在启动时检查有限值并按合法范围夹紧，避免损坏的 UserDefaults 污染实时滤波；
- 重复左键状态在创建 Core Graphics 事件之前即被丢弃，缩放步数对极端整数输入也保持安全。

## V1.2.1 稳定性 / 热路径优化

- PR 自动执行全部 platform-neutral smoke tests 与 Release build；
- 摄像头与 AppController 双层 generation 防止停止/重启后旧帧继续输出；
- 权限异步回调不会在用户关闭后重新启动采集；
- Vision 每只手每帧一次性读取 joints，减少关键点 accessor 开销；
- 键盘合成事件移出 UI / Vision 调用线程；
- 指针按键去重、滚动事件增加数值溢出保护；
- motion timer 从近似 125Hz 修正为真实约 120Hz；
- 方向手势历史扫描改为零临时数组的单次遍历。

## V1.2 的目标

V1.2 不再把“手往回收”当成反向操作，而是把空中操作建模成 **接触笔画 → 重定位 → 重新武装**。重点是连续、低延迟和可恢复，而不是继续增加固定阈值。

### 1. 单向滚动笔画锁：解决“滚完收手又滚回来”

一次双指滚动确认主轴和方向后，同一次接触中的反向位移只作为主手回位，不输出反向页面滚动。

```text
主方向滚动
    ↓
锁定本次笔画方向
    ↓
页面连续滚动
    ↓
手往回收（允许路径有横向偏差）
    ↓
反向位移被吞掉，页面不回弹
    ↓
回到宽松的主轴回中区域 + 稳定约 65ms
    ↓
重新武装下一笔
```

不要求沿原路精确返回；回中判定主要看滚动主轴，横向偏差不会造成误触。

如果希望立刻开始相反方向的新滚动，可短暂放松“双指姿势”，相当于真实触控板上的“抬指再落下”。

### 2. 离散方向手势也加入回程抑制

上一页 / 下一页、系统三/四指方向手势同样会阻止“触发后收手”被再次识别成反方向动作。

### 3. Realtime Capture Pipeline

V1.2 对摄像头 → Vision 链路做了低延迟重构：

```text
AVCapture 快速收帧
        ↓
latest-frame-wins mailbox
        ↓
独立 Vision 串行队列
        ↓
Continuity / Recovery Fusion
        ↓
Realtime Intent Engine
        ↓
120Hz Core Graphics 输出
```

- 移除额外的 `1/30s` 软件节流，避免 29.97~30FPS 输入因时间边界误差被意外降到约 15FPS；
- Vision 忙时不排队旧帧，只保留最新待处理帧；
- 每一帧 Vision 推理使用独立 `autoreleasepool`，避免长期循环中的临时对象积累造成周期性卡顿；
- 优先使用相机支持的原生 420f YUV，回退时才使用 BGRA；
- 若当前 active format 支持 60FPS，则采集层优先 60FPS，Vision 仍按自身吞吐 latest-frame-wins，只为了让待处理帧更新鲜；
- motion timestamp 使用摄像头帧到达时间，而不是 Vision 开始推理时间；显示的 latency 也包含 mailbox 等待 + Vision 推理，更接近真实 camera-to-control 延迟。

### 4. 细小滚动不再被 120Hz 输出层吃掉

低速滚动的输出阈值已显著降低，亚像素/小数滚动继续在 `TrackpadController` 中累积。慢慢移动双指时页面应持续细微移动，而不是“动一段、停一下”。

### 5. 可选双手协同（V1.5）

为保证默认实时性能，双手识别默认关闭；打开后 Vision 最多检测两只手。左手只负责 Hold，右手负责指针、拖拽、滚动和快捷动作。

- **左手：** 先张开拇食指，再捏合保持 300ms，锁定右手当前连续操作；松开 80ms 解锁。
- **右手：** 锁定滚动或缩放后仍可进行独立指针操作；单指姿态准备 200ms，再握拳 500ms 复制、张掌 500ms 粘贴。
- **安全：** 未锁定、未确认物理右手、未通过停留阈值或锁定拖拽期间，不注入剪贴板快捷键；左右手丢失与识别停止都会清理组合状态。
- **视觉反馈：** 透明 HUD 显示左手 Hold 状态、右手快捷操作和锁定的连续动作。

## 使用建议

### 双指连续滚动

1. 双指伸出；
2. 向目标方向移动完成主滚动；
3. 收手时无需精确原路返回，系统不会让页面反向回弹；
4. 回到大致原轴向区域停稳，或短暂放松双指姿势，即可开始下一笔。

### 双手锁定滚动并复制 / 粘贴

1. 在设置中开启「双手联动（左手 Hold 锁定）」与「双手复制 / 粘贴快捷手势」。
2. 右手用双指开始向下滚动，左手拇食指先张开再捏合保持至少 300ms，HUD 显示锁定。
3. 右手回到单指姿态保持至少 200ms，再握拳保持至少 500ms，执行 ⌘C。
4. 右手再次单指保持 200ms，再张开手掌保持 500ms，执行 ⌘V。
5. 左手松开捏合约 80ms 后解除锁定，连续滚动停止。按需在目标应用中先建立文字选区及焦点。

### macOS 实机验收

- 使用同一摄像头轮流交换双手位置，确认 **物理左手** 才能锁定，手的位置不决定左右角色。
- 在 Safari、文本编辑器中验证持续上下滚动、右手指针与 Cmd+C / Cmd+V；防止短时握拳/张掌误发快捷键。
- 验证短暂遮挡、右手消失、左手消失与完全停止摄像头帧输入；确保输出停止，不会一直滚动或卡住鼠标按键。
- 验证暂停/停止、模式切换、关闭双手功能、撤销辅助功能权限后的安全行为。
- 使用 Debug/Release 分别测试 30fps/60fps 相机设备、低光、全屏、多桌面和 HUD 开关。

## 构建

```bash
./build_release.sh
./install_local.sh
pkill -x GestureControl 2>/dev/null || true
open /Applications/GestureControl.app
```

默认只编译当前 Mac 的本机架构。完整构建日志：

```text
build/xcodebuild.log
```

若编译失败，脚本末尾会输出 `REAL BUILD DIAGNOSTICS`。

## 实时性的边界

V1.2 已尽量把软件侧的排队、周期性回收卡顿和手势回程歧义压低，但摄像头 + Vision 与硬件触控板不同：相机帧周期和 Vision 推理仍构成物理延迟下限。因此“接近实时、连续可用”是目标，不能承诺与 MacBook 内建触控板完全相同的毫秒级延迟。界面中的 FPS、Vision latency、稳定度、Continuity 和 hold 指标用于继续实机调优。
